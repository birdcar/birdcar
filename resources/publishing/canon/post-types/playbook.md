# Post type: how-to playbook

Job: an owner can act on it without hiring Nick.

Length: 1,200 to 2,000 words.

Structure:

1. The move, in one sentence.
2. Who this is for and what it will not fix.
3. The steps.
4. What the reader does not have to do.
5. How to tell it worked.
6. When it needs more than this.
7. The invitation paragraph.

Rules:

- Steps use "how I" framing where possible. Use a numbered list only when the steps are genuinely sequential. One task list ("this week") is allowed.
- Show phasing: the smallest useful version first, then what comes later, then what can wait.

Frameworks (pick one per post, or a primary plus one for a single section, and read its "When NOT to use" first):

- `frameworks/socratic-path.md` when the questions are ones owners really ask ("is this worth fixing?"). Its own file warns against making readers wait for the answer, so the answer is already in the first paragraph and the question chain shows the reasoning.
- `frameworks/the-petal.md` for several independent plays around one thesis (three places follow-ups die). Keep petals roughly equal in weight.
- `frameworks/three-act.md` as the safe default for a single throughline.
