Implementation Notes — Phase 1

Publishing Agent Simplification · 2026-09-25 · Native agent configuration and budget-free execution

Preflight — record-rule appended instead of replacing

Context
The spec requires the rule change via Boost record-rule, with the old sentence replaced rather than left beside a new one. The working tree already carried the intended wording (scout risk). Calling record-rule with the existing title appended a second, identical section.
Decision
Called record-rule (so the rule's provenance is the Boost tool), then removed only the exact duplicate section it appended, leaving .ai/rules/ai.md with one section whose text is the record-rule note. No rule text was hand-authored.
Alternative
Leaving two identical sections, or skipping record-rule because the text was already present.

Per-agent configuration — dotted model identifiers

Context
The allowlist is keyed by OpenRouter model IDs such as google/gemini-3.8-flash. Laravel's dotted config() lookup splits on the dot in '3.8' and silently returned null, so allowlisted models read as unknown.
Decision
EditorialAgent reads the whole publishing_agents.models array and indexes it by the full ID (modelDefinition()). Covered by the per-role request-body tests.
Alternative
Renaming keys or storing IDs as list values with an id field.

Per-agent configuration — token and timeout allowances

Context
The spec asks for role-appropriate output allowances that fit the job/worker timeout ordering but gives no numbers. OpenRouter documents that max_tokens covers reasoning plus visible output.
Decision
Native #[MaxTokens] attributes per role: 4k Interviewer, 6k Buyer/Reconciler, 8k Researcher/Voice, 12k Planner/Fact/Recheck, 16k Drafter. A code-owned 50s http_timeout (agent timeout() method) stays below Horizon's 60s supervisor timeout and the documented queue:work --timeout=600. Recorded in the spec's research section.
Alternative
Raising Horizon's timeout or giving the Drafter a longer timeout than the Horizon supervisor allows.

Typed settings — package docblock parser

Context
Spatie settings resolves property types from docblocks and rejects array-key and mixed, so the stored overrides cannot be typed as untrusted mixed data.
Decision
Kept @var array<string, string>; every read path revalidates (runner pauses with an actionable error for a non-allowlisted stored override; overrideModel/resetModel drop unknown roles and models on the next save).
Alternative
A custom cast or a Data object for one small array.

Typed settings — published config and cache knobs

Context
The spec says to publish the package config but add no new environment knobs; the published file reads SETTINGS_CACHE_ENABLED and SETTINGS_CACHE_MEMO.
Decision
Published config/settings.php, hard-coded cache enabled/memo to false, and registered PublishingAgentSettings explicitly alongside auto-discovery.
Alternative
Keeping the env() reads from the stub.

Execution — 429 retry mechanism

Context
The failure policy allows a pre-generation 429 to use the 'existing bounded retry/backoff mechanism'. In reality failOrPause() only marks the activity Failed with available_at +1 minute until run_count exceeds limits.max_retries, then pauses. Recovery re-dispatches only Pending work, and the job has no tries/backoff, so a Failed activity reruns only when something redelivers it.
Decision
Kept that existing behaviour for non-continuation 429s with a fixed message, and added no retry service (spec L213). A 429 during an approval continuation pauses instead, because retrying could replay resolved Decisions.
Alternative
Adding Failed rows to recovery or giving the job tries/backoff, which would expand the workflow.

Execution — classifying failures without reservations

Context
Previously any exception after a reservation paused, and other exceptions went through failOrPause. Without reservations, the runner needs another way to tell a known outcome from an uncertain one.
Decision
The runner tracks whether the provider was invoked and whether a response arrived. Failures before invocation (credentials, invalid model config, conversation ownership) pause with their application message. HTTP 400/401/402/403/404/422 pause with a fixed actionable message and error_reason, never echoing the response body. Timeouts, disconnects, 5xx and unknown errors pause as uncertain. An unusable response after a fresh call goes through failOrPause; after a continuation it pauses, so answered Decisions are not replayed.
Alternative
Treating 5xx as retryable (a 504 can be an uncertain outcome) or reusing failOrPause for continuations.

Execution — test seam between claim and call

Context
The old revalidation test injected a mutation through an EditorialModelBudget::quote() subclass, and that class is now deleted.
Decision
Tests register an EditorialActivity::saved listener that fires when the claimed Running activity first records ai_conversation_id. That save happens after the claim and before confirmBeforeInvocation(), so it is a real model event with no production hook.
Alternative
Adding an injectable callback or keeping a pricing class only for tests.

Execution — model snapshot and Auto pinning

Context
The spec says to capture the execution choice at first invocation and pin Auto continuations to the returned concrete model, but gives no snapshot shape.
Decision
model_snapshot = {requested_model, model, reasoning_effort, returned_model}. It is written inside the pre-invocation transaction, and model is replaced by the returned model when Auto was requested. If Auto returns no usable concrete model with pending approvals, the activity pauses with MODEL_CONTINUITY_ERROR. Continuations read only those keys and ignore legacy provider/pricing keys, and a legacy snapshot whose model is still valid continues on that model. A retry of a Failed non-continuation activity resolves current settings again.
Alternative
Reusing the snapshot for every retry, which would stop an owner from fixing a bad override.

Schema — legacy pause classification

Context
Reservation state is needed to classify budget-era pauses, and the forward migration deletes it.
Decision
Before dropping the table, the migration rewrites activity pause_reasons. The 14 known pre-call blocker messages with no open (reserved/unknown) reservation get EditorialActivity::LEGACY_PRE_CALL_PAUSE_REASON, which attempt resume() now returns to Pending alongside 'Publishing attempt paused.'. 'Billing outcome is unknown.' and any pause with an open reservation get an explanatory protected reason. Budget-written attempt pause reasons are rewritten with actionable wording. The migration also copies generation IDs into null editorial_activities.generation_id and strips financial keys from model_snapshot, using portable query-builder chunks.
Alternative
A mass status reset, or classifying at runtime after the reservation data is gone.

Scope — unlisted required changes

Context
The scout identified dependencies outside the spec's file table.
Decision
Changed tests/Feature/Publishing/ReleaseReadinessTest.php (dropped its AgentBudgetReservation fixture and renamed the test; evidence-freshness assertions kept), the dashboard's '$5 agent allowance' copy, tests/Pest.php (shared setPublishingAgentsPaused() helper, because Pest helper functions are global and eight files need it), and the spec's research section (catalog and docs recheck, per Rollout). Preflight — Boost documentation search

Context
Spec §1.2 asks for Boost search-docs before API-dependent edits.
Decision
Relied on the installed vendor source for laravel/ai 0.11.2 and spatie/laravel-settings 3.9.0 (Promptable resolution, TextGenerationOptions, OpenRouter request builder, settings container, migrator and docblock resolver), because the installed source is authoritative for these exact versions. database-schema was used against the live PostgreSQL database and matched the historical migrations.

Version-agnostic documentation, which would not reflect 0.x SDK internals.
