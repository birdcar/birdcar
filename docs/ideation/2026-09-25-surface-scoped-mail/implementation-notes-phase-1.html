Implementation Notes — Phase 1

Surface-Scoped Mail · 2026-09-25 · Surface mail foundation

Admin invitation / Queued reset — shared link trait (new file)

Context
The spec lets AdminInvitation keep its resetUrl() / expiresInMinutes() logic, and has PasswordReset::toMail() build the same admin-origin link. It lists no shared file.
Decision
I added app/Notifications/Admin/BuildsAdminPasswordLinks.php, a trait used by both notifications. It holds the link builder (admin origin + route(..., false), never url()), the broker expiry, and the guarded routeNotificationFor('mail') recipient. Both notifications keep toMail(object $notifiable), as the spec shows.
Alternative
Copying the ~20 lines into PasswordReset, or typing toMail(User $notifiable) to drop the method_exists guards. I rejected the second because it changes the existing signature.

Surface Mailables — build() clears earlier From entries

Context
The spec snippet calls $this->from(...) in build() and relies on from[0] winning. A subclass constructor that called ->from('spoof@…') would still hold from[0], because build() runs later and appends.
Decision
build() sets $this->from = [] before it adds the settings sender, so settings always hold from[0], whatever a constructor or earlier render() did. There is a known gap left: an envelope() from with the same address and a different name replaces the display name, because Laravel's setAddress() de-duplicates by address and keeps the last entry. The domain can't change, so I accepted this. Phase 2's rule should say so.
Alternative
Overriding buildFrom() to re-apply the sender. That goes beyond the documented build() seam.

Admin invitation — the sender pre-flight catches more than InvalidArgumentException

Context
The spec converts InvalidArgumentException from sender() into AdminInvitationException. A missing row throws Spatie\LaravelSettings\Exceptions\MissingSettings, and a null or array payload throws TypeError on a typed property. InviteAdmin catches neither.
Decision
assertValidSender() catches InvalidArgumentException|MissingSettings|TypeError and also resolves replyToAddress(), because build() resolves it too. That makes the Failure Modes row ("the invite pre-flight fails before provisioning") hold. A dataset test covers both the off-domain and the missing-row cases.
Alternative
Catching Throwable. That would misreport a database outage as "invalid sender settings".

Surface Mailables — generated stubs trimmed; mail views keep the stock layout

Context
make:mail adds Queueable, SerializesModels and an empty attachments(). The spec says the invitation copy moves "unchanged from the MailMessage".
Decision
I removed the unused traits and attachments(), because the Mailables are never queued (the notification is). The markdown views reproduce Laravel's notification template: heading, lines, button, Regards, salutation and the "trouble clicking" subcopy with the raw URL. The rendered email therefore matches what MailMessage produced.
Alternative
A shorter custom layout without the salutation and subcopy. That would change the copy the spec said to keep.

Queued reset — the token is plaintext in the queue payload (owner decision)

Context
Queuing PasswordReset serializes the reset token into the queue store. The spec doesn't mention encrypting it.
Decision
I didn't add ShouldBeEncrypted, following the spec. The owner should decide: implementing Illuminate\Contracts\Queue\ShouldBeEncrypted on PasswordReset is a one-line native hardening.
Alternative
Adding it quietly. That is a behavior change nobody specified.

Local environment — settings rows need a migrate

Context
The local .env keys were renamed with key-anchored sed, and BIRDCAR_{ADMIN,MARKETING}_MAIL_MAILER=smtp were appended. No values were read or printed.
Decision
I didn't run php artisan migrate on the local database. Until the owner runs it, the new admin_mail / marketing_mail rows don't exist, and a local admin:invite stops with "Admin mail sender settings are invalid". That is the intended pre-flight. Tests seed the rows through RefreshDatabase.
Alternative
Migrating the owner's local database without asking.
