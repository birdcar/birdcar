Implementation Notes — Phase 5

Consistent Voice Publishing · 2026-10-12 · Exemplar retrieval

Pre-flight — Laravel Cloud pgvector support

Context
The spec says to confirm Laravel Cloud Postgres supports CREATE EXTENSION vector before shipping the migration, and to stop if it does not.
Decision
Laravel Cloud's Serverless Postgres docs (laravel.com/cloud/docs/resources/databases/postgres) state it supports pgvector, so the phase proceeds. Read-only CLI checks could not confirm which database is attached to production: `cloud database-cluster:list` returns 400 (the CLI asks for an include the API no longer allows), and `environment:get` returns databaseSchemaId null, but the same response also lists the app with no environmentIds, so its relation fields are not populated and prove nothing. Owner gate: before deploying, confirm production is attached to a Laravel Serverless Postgres database. On SQLite or MySQL, `Schema::ensureVectorExtensionExists()` throws during `migrate --force` in the deploy command.
Alternative
Stopping the phase. The documented support is the condition the spec names, and mutating Cloud to probe further is gated.

ApprovePublishingStage — retrieve only when the approval will start a Draft

Context
The spec says to retrieve once per plan approval for blog posts. Agents are paused by default, and a paused plan approval never starts a Draft (no other path starts one).
Decision
Retrieval runs only when agents are unpaused, the piece is a blog post, and the approval is for a plan. It runs before the transaction. A paused approval leaves exemplar_context untouched and makes no request. Retrieval also returns early with no request when the query text is empty or no candidate rows exist, so the existing plan-approval tests send nothing.
Alternative
Retrieving on every plan approval. That spends on approvals that never produce a Draft, and every paused test approval would reach the retriever.

IndexPublishedExemplar — guard against paid calls from the publish hook

Context
The context map notes the hook runs inline in tests (sync queue plus afterCommit), and the local .env carries a real OpenRouter key.
Decision
The job syncs sections but skips embedding while publishing agents are paused, since the pause is the kill switch for automatic paid calls; the backfill command embeds the rows later. The job catches any Throwable and report()s it, so indexing never fails publishing. ExemplarEmbeddings also refuses to send a request when the openrouter-embeddings key is blank, which matches CI.
Alternative
Pinning OPENROUTER_API_KEY to empty in phpunit.xml. It would break the paid tests/Manual live trial, which reads the real key from .env through the same phpunit.xml.

ExemplarEmbeddings — a shared service not listed in the spec

Context
The indexer and the retriever both call `Embeddings::for(...)->dimensions(1536)->generate(provider: 'openrouter-embeddings', model: 'openai/text-embedding-3-small')` and must both check the vector size.
Decision
Added app/Services/Publishing/ExemplarEmbeddings with PROVIDER, MODEL and DIMENSIONS constants and one embed() method. It refuses a blank key, checks the vector count, and requires exactly 1536 floats per vector, throwing a clear error otherwise, so the row keeps a null embedding.
Alternative
Duplicating the call and the checks in both classes.

IndexExemplarSections — the text walker, captions and long blocks

Context
The spec names CheckArticleRelease::documentText as the pattern. It joins every text node and double-counts payload nodes that carry both the legacy text key and content.
Decision
Reused LintTarget::fromDocument, the walker the voice linter already uses. It prefers content over the legacy text key, flattens lists and blockquotes, skips code blocks, replaces inline code with a space, and includes note/callout titles and chart/diagram captions as the owner's prose. Whitespace inside a block is collapsed. A single block over 4,000 characters stays whole, with no sentence split. The embedded input is the heading, a blank line, then the text. The content_hash follows the spec: sha256 of the heading, a newline, then the text.
Alternative
A sibling walker that keeps inline code text. That is more code for archive and consultancy posts that rarely use inline code.

StartEditorialActivity — which inputs carry retrieval, and how ReviewVoice matches the Draft

Context
The spec says Draft and ReviewVoice on blog posts get canon.retrieved_exemplars and canon.retrieval_status with the same voice-only label, and that a retried draft and its reviewer see the same sections.
Decision
Only blog-post Draft and ReviewVoice inputs carry the two keys; every other kind and every kit piece omits them, so their prompt hashes are unchanged. The existing canon.exemplar_label is reused rather than adding a second label. ReviewVoice copies the sections and status frozen into its Draft: the Draft named by draft_activity_id when it is a Draft of the same attempt (a forged id falls back), otherwise the latest Draft of the current review cycle. Without a Draft it uses the attempt context. The status is `none` when the attempt never retrieved, and `stale` when the stored query_hash no longer matches the brief, angle and plan, for example after a rethink.
Alternative
Freezing from the attempt context every time. A re-approval between the Draft and its review could then show the reviewer different sections.

EditorialAgent — telling agents what retrieved sections are

Context
The common rules and role rubrics mentioned only input.canon.exemplars.
Decision
Added one sentence to the common rules after the existing exemplar sentence, which the contract test asserts verbatim. It says retrieved sections are the owner's earlier published writing, chosen for topical closeness, under the same label: imitate only their craft, never reuse their anecdotes, numbers or audience, and never cite them as evidence. Canon role files are unchanged, so the canon version does not move.
Alternative
Editing roles/drafter.md and roles/voice-reviewer.md, which would change the canon version for every activity.

PublishingIndexExemplars — command shape

Context
The spec leaves the meaning of --article open.
Decision
--article takes a slug. The command syncs, then embeds each article separately, prints its created, pruned and embedded counts, keeps going after a failure, and exits non-zero if any article failed. Without --article it also visits articles that still have rows but are no longer eligible, so they get pruned. It ignores the agent pause because it is an explicit owner action. It is not scheduled, and its description says a model or dimension change needs a re-embed migration. No production confirmation flag was added.
Alternative
Taking an id, or adding a --confirm-production flag like publishing:import-archive.

ExemplarRetriever — limits

Context
The spec does not cap sections per source article and does not set a timeout.
Decision
No per-article cap: all four sections may come from one essay. The query embedding uses a 15-second timeout because it runs inside the owner's approval request; indexing batches use 60 seconds. A failure reason is the exception's class name and message, capped at 300 characters. It never contains the API key.
Alternative
A one-section-per-article cap, which the spec does not ask for.

Migration — filename and rollback

Context
make:migration produced a 2026_10_12 timestamp, and the spec names 2026_10_02_200000.
Decision
Renamed the migration to the spec's filename (it sorts after 2026_10_02_100000). Rolling back drops the table and the exemplar_context column but leaves the vector extension installed. An optional ExemplarSectionFactory was added with an embedded() state that the tests use.
Alternative
Dropping the extension in down(), which could break other objects that use it.
