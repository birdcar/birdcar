Implementation Notes — Phase 7

Consistent Voice Publishing · 2026-10-12 · Publishing board

Moves — Ready to Scheduled hands over to the workspace

Context
Spec step 4 says to reuse the workspace's release scheduling dialog. No such dialog exists: scheduling is preparing a release with a publish time (publish) and then approving that exact release (approve), both in the release checklist.
Decision
Took the spec's fallback. MovePublishingPiece returns needsDialog('release') after a publish policy check, and the board redirects to the workspace, which opens on the release tab for Approved pieces, with a status line explaining the two steps. Say so in the commit.
Alternative
Building a scheduling modal on the board, which would duplicate the checklist and its readiness checks.

Moves — park, kill and unpark use the develop policy

Context
The spec says to authorize park and kill with write, but AdvancePublishingAttempt::park and abandon require publishing.develop, so a write-only user would pass the board check and then fail inside the action.
Decision
Park, kill and unpark call Gate::forUser($actor)->authorize('develop', $piece), which also enforces ownership. Ideas to Shaping uses develop; Ready to Scheduled uses publish. The card menu only offers moves the viewer's policy allows.
Alternative
Loosening AdvancePublishingAttempt to accept write, which would widen who can stop agent work.

AdvancePublishingAttempt — new unpark() requeues work a worker paused

Context
No unpark() existed. A worker that claims an activity while its attempt is parked pauses it with “The publishing attempt is blocked or no longer current.” before any provider request, and nothing resumes that reason, so an unparked piece would show a failure with no Retry.
Decision
Added unpark() beside resume() (develop permission, same mutation guard). When the park clears and the attempt is not also paused, activities paused with that exact reason return to Pending, like resume() does for its reasons. The reason became EditorialActivity::BLOCKED_ATTEMPT_PAUSE_REASON, used by RunEditorialActivity::passesExecutionChecks. Results that came back after a park (“…returned after the publishing attempt was blocked or replaced.”) are not requeued, because requeueing would pay for the request again.
Alternative
Leaving those activities paused and only showing the reason on the card.

Moves — parking or killing withdraws a scheduled release

Context
Parking or killing a Scheduled piece left its release scheduled, so publishing:publish-due would fail on every run, and after an unpark a past-due release would publish on the next run.
Decision
Park and kill call ManageArticleRelease::withdrawScheduledReleasesForAttemptId, the helper the workspace's own withdraw button uses, and the message says so when a release was withdrawn. Like the workspace button, the stage is left as it is; an unparked Scheduled piece is rescheduled from the release checklist.
Alternative
Refusing park and kill for Scheduled pieces until the owner withdraws the release in the workspace.

Moves — Ideas and Published can't be parked or killed

Context
The spec says “any column to Parked or Killed”, but ideas have no attempt to hold the reason, published attempts are terminal, and archive imports have no attempt at all.
Decision
Both are refused with a message that says why (“Ideas are already off the clock…”, “Published work is already live…”). Killed pieces can't be moved either; the workspace's “Develop this idea” starts them again. A parked piece can be killed, and only unparks onto its own stage column (the message names it).
Alternative
Creating an attempt for an idea just to park it, which would leave an attempt with no interview.

BoardColumn — reading of the Writing rule

Context
Read literally, “in_review with no completed draft on the current revision” would move a reviewed piece back to Writing on the owner's first autosave, because every save is a new revision.
Decision
Writing means a draft, voice-rule repair or kit draft is pending or running, or no draft (draft, lint_repair or draft_kit) has completed in the attempt at all. Everything else at in_review is Review. The completed-draft flag is a withExists on the attempt, so it is exact even when the latest draft row failed. A plan approved while agents were paused (no Draft created) shows in Writing.
Alternative
Comparing the draft's target revision with the working revision.

PieceStatus — precedence and rules

Context
The spec lists the states but not which wins, and leaves out an interview waiting for the owner's answers.
Decision
Failed beats running, running beats waiting, waiting beats idle. Failed means the newest non-stale activity is failed or paused (reason pause_reason ?? error_reason). Running says “Running” for a running activity and “Queued; agents paused” for pending work while agents are paused globally. Waiting covers interview answers, the angle, a ready plan, undecided blocking findings, an unaccepted package (checked in SQL against the package-{id}- mutation id), a prepared release on the working revision, and a drafted and reviewed kit piece without a kit approval. A paused attempt shows as waiting with its pause reason; parked, killed and published pieces are idle (the card shows the parked or killed reason). Kit statuses show on their chips; the flagship's status is its own.
Alternative
Rolling kit statuses up into the flagship card's status.

Board — refusals show in an in-board alert, not a toast

Context
The spec's error handling says “Toast with the action's error”, but the admin layout has no <flux:toast />.
Decision
Refusals and confirmations render in a dismissible flux:callout above the board (role="alert" for refusals, role="status" otherwise), which keeps the layout untouched and is easy to assert. The card snaps back because the handler always re-renders from server state.
Alternative
Adding <flux:toast /> to layouts/admin.blade.php, a file the spec doesn't list.

Board — caps and stale-board detection

Context
Only the Published column has a cap in the spec. Each card's column is what the server must compare against, but wire:sort only sends the item key, the position and the receiving group id.
Decision
Published is a separate query capped at 12 (newest first_published_at, then id) plus a count, with a link to the library. Ideas and Killed are uncapped, because nothing else lists saved ideas or killed pieces; Killed is collapsed by default on the client. Each card's sort key is {id}:{column}, so MovePublishingPiece re-derives the column under a row lock and refuses with “This piece moved; refresh the board…” on a mismatch. The board loads in a fixed number of queries (asserted with 3 and 30 pieces).
Alternative
Paginating Ideas as the old dashboard did.

Board — polling and drag behavior

Context
The board polls every ten seconds; a poll during a drag can fight SortableJS, and Flux's kanban parts are Blaze-folded.
Decision
wire:poll.10s.visible sits on the board region, and the component's script cancels poll actions while body.sorting is set. The wire:sort attributes live on plain divs (handler first, then group, group id and config) rather than on folded Flux components, use wire:sort.ghost so the drop placeholder is visible, restrict dragging to cards, and turn the animation off under reduced motion. The card menu repeats every allowed move as buttons for touch screens.
Alternative
Isolating the cards in a Livewire island, which would also scope the move actions and the reason modal to the island.

Tests — dashboard tests rewritten, not deleted

Context
Eight tests drove the deleted dashboard component, and three asserted list behavior the board replaces (independent pagination, created_at tie-breaks, published work hidden from /publishing).
Decision
They point at admin.publishing.board. The pagination test now checks that every idea shows and Published is capped at 12 with a library link; the tie-break test checks newest-first order with id tie-breaks; the “listed separately” and “terminal live title” assertions now expect published work in the Published column. The heading “Publishing workspace” and the route name admin.publishing.dashboard are kept, so the Journey test and every link keep working.
Alternative
Deleting the obsolete list tests.

Codebase surprise — ReadAdminHome's open-findings filter skips most findings

Context
ReadAdminHome filters findings with whereNotIn('reconciliation_state', ['duplicate', 'superseded']). The column is nullable and only reconciliation sets it, so in SQL that excludes every finding with a NULL state.
Decision
The board's own filter treats NULL as not reconciled. ReadAdminHome is unchanged because it is out of this phase's scope; the owner may want the same fix there.
Alternative
Changing ReadAdminHome in this phase.
