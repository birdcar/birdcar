Implementation Notes — Phase 4

Consistent Voice Publishing · 2026-10-12 · Frameworks, sharper reviewers and packaging

Process — context map not rewritten

Context
The engine asked for the scout's Phase 4 context map to be written verbatim to context-map.md before building.
Decision
The write was interrupted partway, and the map was not re-sent; context-map.md still holds the Phase 3 map. The build used the Phase 4 map from the prompt directly.
Alternative
Retrying the verbatim write.

Plan gate — hand-written plans need no framework choice

Context
The spec says plan approval requires plan.framework.chosen. Nine test helpers build plans by hand through rethink(plan:), and no UI does.
Decision
Only agent plans (source = agent) must carry a chosen framework that equals the primary. A plan the owner wrote carries its own structure. Since chosen sits inside attempt.plan, all four plan-hash copies cover it with no other change.
Alternative
Requiring a framework on every plan, which would mean editing nine helpers for a path no owner uses.

Plan gate — re-plans and repeat choices

Context
The spec does not say whether a re-plan records the choice, and two edge cases contradicted each other: choosing the same slug twice should return one activity, yet choosing is refused while a plan runs.
Decision
A completed re-plan stores framework_choice as chosen (validation already forces it to be the primary), so no extra click is needed. Choosing the same slug while its re-plan is pending returns that activity; choosing a different one is refused. Picking another framework clears chosen first, so the old plan cannot be approved while the re-plan runs.
Alternative
Requiring one more click after the re-plan.

Brief — post type can be null; owner picks before angle approval

Context
A null postType from the Interviewer breaks six fixtures if rejected, and setting the post type after angle approval invalidates the angle.
Decision
The schema enum is nullable. A null keeps any post type the owner already chose. The workspace offers a post-type select before angle approval and disables Approve angle until one is saved. choosePostType goes through rethink(brief:), so later changes withdraw the approvals as any brief change does. Angle approval does not hard-require a post type; a plan without one fails validation with a clear reason.
Alternative
Hard-gating angle approval, which would break most existing approval fixtures.

Catalog — departures from the spec sketch

Context
The spec's avoid pair ["reverse-chronology","kishotenketsu"] names a framework with no file. The guide says short pieces allow low complexity only, yet post-types/work-story.md lists Story Circle (medium).
Decision
The kishotenketsu pair was dropped. Work stories keep Story Circle: the spec's rule excludes only high complexity at 1,500 words or fewer. Every framework has min_words 800 (each file has a short form), except the Jeremiad at 1,500. With this catalog, length exclusion never removes a listed framework, so a test builds its own catalog to prove the rule. frameworks/guide.md was added to the Planner rubric, and the catalog is frozen into Interview and Plan input as canon.catalog.
Alternative
Keeping the unknown slug and letting the validator ignore it.

Canon — metadata rules also go to the Drafter

Context
The spec adds voice/metadata-rules.md only to package, but contract G2 and Phase 8 need every lint id stated in a draft-role file.
Decision
The file is listed under draft too. The Drafter test now checks the five metadata statements reach the Drafter's system message, and the Drafter rubric no longer asks for metadata proposals.
Alternative
Listing it only for package, which breaks Phase 8's save check.

Packager — what fails the paid activity

Context
The spec hard-fails the five metadata rules; it is silent on character rules and on whether the title must be one of the ten options.
Decision
Any metadata lint hit fails the package, character rules included (em dash, curly quotes, emoji, exclamation point), so the owner never gets a package release would block. The title need not be one of the options. The greatest-hits tag is capped at 80 characters.
Alternative
Failing on the five metadata rules only, and leaving character-rule hits to block at release.

Packaging trigger — rechecks and idempotency

Context
"Review finished" is not stored, and finishing review again with accepted dispositions can start a recheck after a package exists.
Decision
Eligibility is derived: the reviewed revision has a completed reconciliation, no undisposed blocking or conflicting finding outside lint, and either a completed recheck on the current revision or none used. Any completed recheck starts packaging; unresolved items still block release. A recheck that starts after packaging marks earlier packages stale, and acceptance refuses a package older than a recheck. The post-recheck package uses batch key package-{cycle}-{revision}-after-recheck, and Package idempotency is revision-based like the review kinds.
Alternative
Packaging only after a fully resolved recheck.

Release lineage — one implementation

Context
ManageArticleRelease::approve had its own copy of the lineage logic, which the spec did not mention. Without changing it, approval threw after packaging.
Decision
ManageArticleRelease now delegates to ReleaseFreshnessManifest::reviewLineage, using its revision_ids and recheck_activity_ids. The duplicate helpers were deleted. A new metadata_only mode walks parent revisions while the document fingerprint stays identical, so a run of metadata-only saves stays covered.
Alternative
Patching both implementations separately.

Release — SEO title, slugs, archive essays

Context
Edited archive essays would be blocked by metadata.seo_title.required, and slug rules read metadata.slug rather than the slug typed into the release dialog.
Decision
The SEO title is required only for blog posts that are not archive imports. The workspace release slug now defaults to metadata.slug and follows an accepted package; a different slug typed in the dialog bypasses slug-shape, though slug.unique still guards collisions. Accepting a package never writes articles.slug; prepare does that, as before.
Alternative
Applying the SEO-title requirement to archive essays.

ReadPublishedWriting and pages/writing/[slug].blade.php use metadata.title for the page title.
Decision
Out of scope for this phase and not changed. metadata.seo_title is stored, linted and required, but the public page does not use it yet.
Alternative
Changing the public page in this phase.

Claim manifest — which research counts

Context
The spec says to use the latest completed research of the attempt. Restarting review bumps the review cycle, which would leave the research behind if the manifest required the current cycle.
Decision
The manifest uses the attempt's latest completed research in any cycle. A claim is kept when it has a statement and a quotation, no quotation contradicts it, and it is not marked unresolved (by unresolved, a reason, or an unresolved or unsupported status). Source ids merge integer ids, response-local refs (matched through the research's evidence origin_metadata or URL) and quotation sources, sorted. No research gives [].
Alternative
Requiring the current cycle and angle approval.

Idea title — archive essays

Context
An archive idea's summary title holds the published title with source derived, so a new interview would overwrite it.
Decision
The interviewer's ideaTitle is skipped for articles with an import-origin release, as well as for owner-renamed ideas. A blank title changes nothing; one over 80 characters fails the interview.
Alternative
Applying it to archive ideas too.

Lens markers — buyer sections

Context
The spec names the buyer markers but not which sections they label.
Decision
buyer marks the value equation, discovery marks the publishing test, and commercial-structure marks answer-first and the invitation. The voice rubric gains a Framework adherence section that reads input.canon.framework and input.canon.post_type.
Alternative
Adding new sections just to carry the markers.

Workspace — naming and counts

Context
"Release package" already means a prepared release in the workspace.
Decision
The new panel is called "Titles and search" and its action is acceptPackageProposal. Live counts use [...str].length, so they count code points like mb_strlen. The panel re-lints the fields as typed and lists the hits before the owner saves.
Alternative
Calling it "package" in the UI.
