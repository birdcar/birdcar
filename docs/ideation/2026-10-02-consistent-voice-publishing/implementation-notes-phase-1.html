Implementation Notes — Phase 1

Consistent Voice Publishing · 2026-10-12 · Content ideas and pieces

Step A — Postgres session timezone pinned to UTC

Context
Spec step A said to fix application code when Postgres exposes a real bug. Two release tests failed by 7–8 hours: Herd's Postgres server runs in America/Los_Angeles, and Laravel writes timestampTz values without an offset, so the server read UTC values as Pacific time.
Decision
Added 'timezone' => 'UTC' to the pgsql connection in config/database.php, matching app.timezone. The bug also affects local development, which uses the same server.
Alternative
Changing the server timezone in Herd (machine-local and invisible to the repo), or adjusting the test expectations (that would hide a real bug).

Step A — jsonb key order

Context
Postgres jsonb reorders object keys. Four tests compared jsonb-read arrays with toBe, and WriteArticle's protected-block guard compared blocks with strict !==, which depends on key order.
Decision
The guard now compares PublishingFingerprint::canonicalJson() of both sides, an app fix. The four assertions (AdminPublishingEditorTest, PublishingSessionTest, AgentBudgetTest, PublishingAgentSettingsTest) now use toEqual because they encoded SQLite's key-order preservation.
Alternative
Switching the columns to json, which keeps key order. Rejected as a schema change made only to suit the tests.

Step A — CI 'Load published writing' step left unchanged

Context
The spec asks that this step keep working, assuming an archive data migration stays applied. No such migration exists, and the step calls App\Actions\ReadWriting::all(), a method that does not exist, so the step is already broken (scout risk).
Decision
Added only the Postgres service and job env. The step itself is unchanged, and the owner should decide its fate.
Alternative
Pointing it at ReadPublishedWriting::all(). That would turn it into a real failure, because birdcar_test holds no published rows after the suite.

Step A — Manual live trial guard

Context
tests/Manual/PublishingModelTrialTest.php refused to run unless the connection was SQLite :memory:, so after Step A it would always refuse. The spec's grep check does not cover it.
Decision
The guard now requires pgsql with the birdcar_test database and no URL, and runs migrate:fresh instead of migrate. The trial keeps an isolated, freshly migrated database. Its capture() calls moved to captureIdea().
Alternative
Leaving the guard as it was, which would make the trial permanently unusable.

Data model — content_ideas.author_id nullable, null on delete

Context
The spec has content_ideas.author_id NOT NULL … ON DELETE CASCADE and articles.content_idea_id … ON DELETE RESTRICT. articles.author_id is already nullable with null-on-delete. With the spec's constraints, deleting a user who has articles cascades to their ideas, the restrict foreign key on articles then fails, and the user cannot be deleted.
Decision
content_ideas.author_id is nullable and nulled on delete, matching articles. This also lets the backfill carry over legacy articles with a null author. A test in ContentIdeaTest covers deleting an author.
Alternative
Following the spec literally. That would make user deletion fail for every author who has writing.

Model — ContentIdea shape

Context
The spec sketch says final class ContentIdea and gives no type for summary_title_source.
Decision
The class is non-final like every sibling model. summary_title_source is a string column with SOURCE_DERIVED/OWNER/INTERVIEWER constants, plus TITLE_LIMIT (120), DERIVED_TITLE_LIMIT (80) and UNTITLED.
Alternative
A SummaryTitleSource enum. Rejected because the spec lists no such file; Phase 4 can promote the constants to an enum.

Summary derivation — inline Markdown stripped

Context
The Technical Approach says 'Markdown stripped', but the sketch strips only leading markers.
Decision
deriveSummaryTitle also removes link and image syntax (keeping the text), plus **, __, ~~ and backticks. It removes single */_ only at word edges, so user_id survives. A line that is only a marker is skipped. A word longer than 80 characters is hard-cut. CRLF and multibyte text are handled with \R and the mb_* functions.
Alternative
Stripping leading markers only. That would put raw **bold** into the labels.

Workspace header — untitled heading

Context
articleTitle may no longer fall back to the idea, but the h1 still needs text before a title exists.
Decision
The h1 shows the metadata title, or 'Untitled blog post' (from PieceKind::label()). The idea appears on its own labeled line below, with an inline rename (Alpine toggle, Gate::authorize('update'), then validate, then WriteArticle::renameIdea) shown only to users who can update the article.
Alternative
Putting the labeled idea inside the h1. Rejected because the manual check asks that the idea not read as the title.

Labels — shared Blade components

Context
The spec asks for the same 'Idea' label on the dashboard (both lists), workspace, published list and Admin index, and mentions a separate ideaLabelFor().
Decision
Added anonymous components x-admin.publishing.idea-label (badge plus summary, data-idea-label) and x-admin.publishing.piece-heading (title or labeled idea, with the labeled idea underneath when a title exists). The dashboard's titleFor() returns ?string. No ideaLabelFor() wrapper was added, since the component reads contentIdea->summary_title directly.
Alternative
Copying the badge markup into each of the five sites.

Files outside the spec's list

Context
Scout identified four sites the spec missed.
Decision
ReadAdminHome eager-loads contentIdea:id,summary_title. The voice-sample label in develop.blade.php falls back to 'Untitled' instead of the idea. The release checklist falls back to the payload title, then the working metadata title, then 'Untitled'. session.blade.php holds the header changes.
Alternative
None.

Tests — release slug canonicalization

Context
The spec asks ArticleSlugTest to show that 'release still canonicalizes', but release preparation needs the approval and review fixtures that live in ReleaseIntegrityTest. Those are global helpers that are not loaded when ArticleSlugTest runs alone.
Decision
ArticleSlugTest now covers provisional slugs for captures and added pieces, and slug stability across a rename. The canonicalization assertion (slug becomes live-isolation after prepare) went into ReleaseIntegrityTest's first test.
Alternative
Duplicating about 100 lines of release-prerequisite helpers into ArticleSlugTest.

Process — Step A not committed separately

Context
The spec says to commit Step A on its own as test(publishing): Run the suite on Postgres.
Decision
Under the engine overrides the builder never commits, so all changes are left unstaged. The Step A files are phpunit.xml, .github/workflows/tests.yml, config/database.php, the canonical comparison in WriteArticle.php, the four toEqual test edits and the Manual trial guard. The commit stage can split them out if it wants two commits; note that WriteArticle.php and the Manual trial file also carry Step B changes.
Alternative
None (constrained by the workflow).
