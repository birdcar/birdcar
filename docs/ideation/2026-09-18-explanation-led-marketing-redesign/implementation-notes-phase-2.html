Implementation Notes — Phase 2

Explanation-led marketing redesign · 2026-09-19 · Referral-led marketing journey

Booking — prevent the duplicate modifier-click modal

Context
The spec requires native modified clicks and otherwise limits booking.js changes to theme alignment. The existing handler omitted Alt; browser Meta-click testing also showed Cal opening a modal while the browser opened a new tab.
Decision
Handle modified clicks in capture phase and stop propagation to Cal without preventing navigation. Add focused booking.test.js coverage for tokens, fallback gating and modifiers; leave callback/event semantics for Phase 4.
Alternative
Theme-only edits would leave a demonstrated acceptance failure. A loader or analytics refactor would exceed this phase.

Reporting — one authored static figure in two places

Context
The new figure must explain supplied project facts and be reusable; the homepage needs implementation proof distinct from the free report.
Decision
Use the same id-free semantic HTML/SVG component on the homepage and Work. No extra animation or abstract graph model. Decorative gathering lines support, rather than carry, the explanation.
Alternative
A dashboard mockup implies unsupported artifacts; a second custom animation adds no necessary meaning.

Tests — reader decisions instead of pronoun arithmetic

Context
The spec rejects pronoun counts as evidence of persuasion while requiring strong factual/behavior assertions and no test deletion.
Decision
Replace the existing pronoun-ratio and question-count assertions with visible independent next steps and the concrete homepage buying journey. Strengthen proof boundaries, footer states, report relationships, repeated figures, and exact CTA placement/destination checks.
Alternative
Keeping arbitrary pronoun quotas would constrain clear authored copy without testing the reader’s decision.

Feedback environment — disable local analytics and refresh workers

Context
The initial browser probe found enabled analytics and stale Vite asset URLs in long-running workers. Its application JS returned 404 and no PostHog resource entries were observed.
Decision
Set gitignored POSTHOG_DISABLED=true, block PostHog in QA browser contexts, temporarily cache current config and reload Octane. Verify the rendered body has no analytics configuration before behavioral checks. Remove the temporary configuration cache afterward. Cal was viewed only; no time was selected or booking submitted.
Alternative
Assuming the previous phase’s disabled state persisted would risk live events. No remote PostHog account changes are authorized.

Browser evidence — external iframe capture limitation

Context
Full-page screenshots from document top omit the offscreen Cal iframe even after its DOM loads. Early modal captures also caught the external loading skeleton.
Decision
Retain full-page screenshots as page-composition evidence only. Supply separate calendar viewport captures at 1440/768/390 and a loaded modal capture, waiting for real date controls. Record failed probes as tool/capture issues, not passing evidence.
Alternative
Blank offscreen screenshots do not prove a broken calendar; neither do DOM counts alone prove its final appearance.
