# Publishing — Session workspace

Operate mode, exclusively for the owner. Turn a rough idea into a finished article through interviewing and collaboration. The owner confirmed this structure and explicitly requested expressive motion, show, joy, and magic in daily work.

## Direction contract

THESIS: One article, three working modes; editorial work leads, not a console of agent controls.

OWN-WORLD: Existing Flux Pro, Inter, neutral surfaces, deep-teal light and cyan dark accents; personal, tactile, expressive.

STORY: Capture an idea, interview, approve angle and plan separately, write with passage feedback, approve the exact release.

FIRST VIEWPORT: Persistent article title/save state above Develop, Write & review, Release; a wide active work surface and contextual companion pane. Mobile switches panes. Idea-to-article arrival and verified publication are the signature motion, with interruptible spring continuity elsewhere.

## Scope and boundaries

Publishing landing, article workspace, Published library, and the focused agent Settings form; retain the shared Admin shell. Ideas and Active writing remain distinct. Develop begins native interviewing; Save for later stays passive. Preserve authorization, immutable live releases, exact approvals, bounded review/recheck, structured blocks, protected passages, recovery and stale-edit protection. No new dependencies, agent runtime, marketing redesign, distribution, deployment, paid calls, real publication, or privileged account changes.

## Interaction

Develop pairs focused interview/angle/plan decisions with a readable living brief. Write & review gives the manuscript the dominant continuous surface, with collapsible feedback and sources. Release pairs a legible exact preview with metadata/checks/delivery intent. Public preview is independently styled. Live and working versions stay distinct. Status describes real activity, not fabricated percentages. Nonessential animation is interruptible and has reduced-motion alternatives; joy is a first-class goal, while typing, selection, focus, and save safety remain steady.

## Coverage

Empty and growing libraries; long ideas/manuscripts; notes/charts/diagrams; agents paused/pending/running/questions/failure; pending approvals; advisory versus blocking findings; save/conflict/recovery; scheduled versus genuinely published. Authenticated interaction and owner editorial acceptance cannot be inferred from visual fixtures.

## Built system record

The owner-only Publishing workspace is built in the existing Admin visual system: Flux Pro, Inter, neutral light/dark surfaces, and restrained deep-teal/cyan accent. `/publishing` is creation-first with a large rounded composer; the paper-airplane action develops an idea and starts the native Interview path, while the bookmark saves passively without agent work. Ideas, Active writing, and Published remain separate and owner-scoped with independent pagination.

Article sessions keep the title and save state persistent above Develop, Write & review, and Release. Develop presents readable interview, angle, plan, living brief, activity, sources, and voice samples; angle, plan, and release are explicit text approvals. Write & review gives the manuscript the broad editor surface with contextual feedback, sources, and brief; mobile context replaces the manuscript visually without destroying editor state. Release separates metadata/date/checklist, frozen scoped preview, timezone scheduling, approval, and publication; Published shows live title/date plus draft-in-progress badges.

Settings (`/publishing/settings`) is an Operate-mode form for the owner, gated by the agent configuration capability and linked from the Publishing navigation. Agent requests pair a pause switch with a separate saved-state badge, unsaved-change text, and plain scope copy: in-flight requests may finish, queued work and author answers wait, publication and approvals are unaffected, and unpausing resets nothing. The key notice is boolean only. Models by task lists nine readable roles with purpose, code recommendation, native Flux select (Use recommended, curated models, OpenRouter Auto Router with dynamic-selection copy), pinned or reset-required state, and per-task reset. One explicit Save persists the form. No prices, allowances, spending, or key values appear.

Motion is expressive but bounded to the implementation: Motion springs for mode changes, confirmed-capture arrival in the session header, small confirmed milestones, activity pulse, and a disposable published-only flourish. Reduced motion suppresses decoration. The latest icon composer request is represented by the paper-airplane Develop affordance matching the send/capture action.

Safety behavior is part of the shipped surface: capture-phase guards block unsafe actions while saving or in conflict, stale server updates preserve local edits, and older-revision recovery enters conflict before enqueue. Literal colors were converted to existing zinc/rose tokens; no new shipping raster assets were added.
